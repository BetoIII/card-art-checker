Rain · Card art compliance

Card Art Checker API

Submit card art. Get a Visa compliance verdict: what failed, where on the art, and whether it can ship.

Overview #

A Claude agent reviews the art against Visa's 22 virtual-card rules, backed by 13 automated measurements. Runs take about two minutes, so results are always asynchronous. Every integration follows four steps.

01
Submit
POST the art with ?async=1.
02
Store the runId
Returned immediately.
03
Wait
Analysis runs in the background.
04
Read the result
Poll, or receive it by webhook.

Base URL. https://card-art-checker.vercel.app

Use this URL, not per-deploy …-<hash>.vercel.app URLs, which change on every push.

Quickstart #

Submit a virtual card and read the result.

Submit 
curl -X POST "https://card-art-checker.vercel.app/api/card-check?async=1" \
  -H "Authorization: Bearer $CARD_ART_CHECKER_SECRET" \
  -F "file=@card.png" \
  -F "cardType=virtual" \
  -F "tenantId=9eef553e-4dd3-4e70-b86a-0edc969f447c" \
  -F "reference=cardArtForm_01HX9"

# → { "ok": true, "queued": true, "runId": "msqz4i4j-6fa7c9",
#     "projectId": null, "tenantId": "9eef553e-4dd3-4e70-b86a-0edc969f447c",
#     "reference": "cardArtForm_01HX9", "cardType": "virtual" }
const form = new FormData()
form.append("file", new Blob([artBuffer], { type: "image/png" }), "card.png")
form.append("cardType", "virtual")
form.append("tenantId", tenant.id)
form.append("reference", cardArtForm.id)

const res = await fetch(`${CARD_ART_CHECKER_URL}/api/card-check?async=1`, {
  method: "POST",
  headers: { Authorization: `Bearer ${CARD_ART_CHECKER_SECRET}` },
  body: form,
})

const { runId } = await res.json()
// Store runId. You need it to fetch the result.
Read the result 
curl -H "Authorization: Bearer $CARD_ART_CHECKER_SECRET" \
  "https://card-art-checker.vercel.app/api/result/msqz4i4j-6fa7c9"

# 404 while the run is in progress. This is expected.
# 200 → { "runId": "…", "count": 1, "results": [ … ] }
const res = await fetch(`${CARD_ART_CHECKER_URL}/api/result/${runId}`, {
  headers: { Authorization: `Bearer ${CARD_ART_CHECKER_SECRET}` },
})

if (res.status === 404) return // still running, try again later

const { results } = await res.json()
const [result] = results

if (result.status === "error") return           // the run failed; retry
if (result.outcome === "requires_changes") {
  reject(result.summary, result.blocking_failures)
}

We recommend webhooks over polling: no requests while a run is in progress.

Authentication #

One shared secret authenticates every server-to-server endpoint. Send it in either header:

Headers 
Authorization: Bearer <secret>
x-webhook-secret: <secret>

Request the secret from your Rain contact. The same secret submits checks and reads results.

Async requires the secret. Only authenticated callers can use ?async=1. If you receive an event stream instead of JSON, the secret is not reaching us.

Submit a check #

POST /api/card-check?async=1 Bearer token

Send the art as multipart/form-data with ?async=1. The response returns once the file is parsed; analysis continues in the background. Without ?async=1 you get a browser progress stream, which servers should not use.

Body fields #

file file Required Card art. Virtual: a flattened 1536×969 PNG at 72 DPI. Other sizes and formats are analyzed but fail the structural checks.

tenantId string (UUID) One of Your Rain tenant id. Send this, projectId, or both; requests with neither are rejected. Validated for format only.
projectId string (digits) One of Your Rocketlane project id, if you have one. Must exist in Rocketlane or the run fails (missing_project_id). The result includes the project name.
callbackUrl string Optional Webhook URL for this run. Must be allowlisted; see Webhooks.
declaredProduct string Optional The Visa product the program is provisioned as, e.g. Signature Corporate. The art's identifier must match it exactly, word order included (identifier_tier_mismatch). Accepts a canonical product (Debit … Infinite Corporate), Business, or Classic; other values are ignored. Returned as submission.declared_product.

Responses #

200  Queued

File accepted. Store runId; it is the only way to retrieve the result.

200 application/json 
{
  "ok": true,
  "queued": true,
  "runId": "msqz4i4j-6fa7c9",
  "projectId": null,
  "tenantId": "9eef553e-4dd3-4e70-b86a-0edc969f447c",
  "reference": "cardArtForm_01HX9",
  "cardType": "virtual"
}

400  Rejected

Includes a runId for tracing.

400 application/json 
{ "error": "No file uploaded", "runId": "msr0w4np-1eoerz" }

Other error values:

  • Missing projectId or tenantId
  • Invalid tenantId "…" — expected a Rain tenant UUID
  • Invalid projectId "…" — expected a numeric Rocketlane project id
  • Invalid cardType "foo" — must be "virtual" or "physical"
  • Could not infer card type from "art.bin" — pass cardType=virtual|physical explicitly
  • Multipart parse timed out (upload exceeded 30s)
  • backFile is only valid for physical submissions

A non-multipart request returns 400 with plain text: Bad request: expected multipart/form-data.

Fetch a result #

GET /api/result/{runId} Bearer token

Returns the result object in a one-item results array, the same object a webhook delivers. Poll every 15–30 seconds.

StatusBodyMeaning
200 { runId, count, results[] } Complete. See the result object.
404 { error, runId, hint } Still running, or unknown run. Expected while waiting.
400 { error } Missing runId or Malformed runId. Format: msqz4i4j-6fa7c9.
401 Unauthorized (text) Invalid or missing secret.
502 { error: "Result lookup failed" } Storage read failed. Retry.

Webhooks #

The recommended way to receive results. Setup needs one change on our side: we point RESULT_WEBHOOK_URL at your endpoint, or add your host to RESULT_WEBHOOK_ALLOWED_HOSTS so you can pass callbackUrl per request. Ask your Rain contact for either, plus the signing secret.

A callbackUrl must use https, and its host or a parent domain must be allowlisted (example.com covers hooks.example.com). It overrides the default webhook for that run. An invalid callbackUrl sends nothing and does not fall back to the default.

Verify the signature #

HMAC-SHA256 of {timestamp}.{rawBody}, keyed with your webhook signing secret. The timestamp is signed; reject requests older than five minutes to block replays.

verify.ts 
import { createHmac, timingSafeEqual } from "node:crypto"

const MAX_AGE_S = 300

function verify(rawBody: string, headers: Record<string, string>, secret: string) {
  const ts = headers["x-card-art-timestamp"]
  if (!ts || Math.abs(Date.now() / 1000 - Number(ts)) > MAX_AGE_S) return false

  const expected = "sha256=" + createHmac("sha256", secret)
    .update(`${ts}.${rawBody}`)
    .digest("hex")

  const a = Buffer.from(expected)
  const b = Buffer.from(headers["x-card-art-signature"] ?? "")
  return a.length === b.length && timingSafeEqual(a, b)
}

Verify the raw body before parsing JSON. Re-serialized JSON will not match.

Delivery #

Retries3 attempts, 500ms then 1s apart
Retried on5xx, 408, 429, timeouts, and network errors
Not retriedAny other 4xx
Timeout10s per attempt
Near the deadlineSkipped if it cannot finish within the run's 280s budget
Physical resultsNever sent (schema_version: "0-internal")
Delivery failureLogged on the run. Never fails the analysis.

Return 2xx fast and process afterward. Retries can deliver a result twice; deduplicate on run_id + attachment_id. Missed deliveries stay available at GET /api/result/{runId}.

Fields #

FieldNotes
outcome The review decision. Branch on this.
status Legacy: pass, fail, or error. Do not branch on it; approved_with_notes reads as pass. error means the run failed; see failures.
summary One or two sentences for the designer. Fits VARCHAR(1024).
blocking_failures Ids of failing blocker checks and technical checks. Failing required checks are not listed but still yield requires_changes. For every failure, filter checks and tech_checks on status: "fail".
checks Every catalog check (22 for virtual), always. An unreported check is unverified, never a silent pass.
checks[].id Stable. Bind to this. See the check catalog.
checks[].name Display text. Do not match on it.
checks[].reason_code Set on fail and warning; otherwise null. A code from the catalog or a universal code.
checks[].marker Issue location as 0–1 coordinates; {x: 0.84, y: 0.82} is lower-right. Omitted when the issue has no single location.
checks[].merged_from Present when several checks were judged together (e.g. "No EMV chip / hologram / magstripe"). They share one verdict; treat them as not independently assessed.
tech_checks id, status, actual, required, note (or null), borderline: true on a near miss, and measurements when available.
counts Checks per status. Zero counts are omitted.
project · tenant The ids you sent, plus the Rocketlane project name. Unsent ids are null.
submission file_name, plus declared_product if recognized.
trigger reference echoes your value.
colors Extracted from the art, for comparison with the tenant's declared colors.
unmapped_checks Should be []. If not, nothing is lost, but tell us.

schema_version: "1.0" may add fields. Ignore unknown fields.

Check catalog #

Errors & failures #

A run that cannot finish still returns a result, so a broken run is never mistaken for a rejected design. It arrives like any result, through GET /api/result or a card_art_check.failed webhook. Runs nearing the 300-second limit publish function_timeout, so polling always ends.

Never reject a design on a failure result. Leave the submission open and retry.

Limits #

Run durationAbout two minutes; 300s maximum. The visual review needs 150s remaining to start, otherwise visual_budget_exhausted.
