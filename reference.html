Card Art Checker API

Submit a card design, get back a structured compliance verdict against the Visa brand rules — which checks failed, where on the art, and whether the design can ship.

Overview #

A check is a visual review: a Claude agent inspects the art against Visa's 22 virtual-card rules, alongside 13 deterministic measurements, and returns a decision. It's one request: post the art with your Rocketlane project id, keep the connection open while progress streams back — usually about two minutes — and the verdict arrives as the last event.

01
Submit
POST the art and your Rocketlane projectId to /api/card-check.
02
Wait
Progress events stream back while the check runs, usually about two minutes.
03
Read the verdict
The last event, complete, carries the full result.

Base URL. https://card-art-checker.vercel.app

Use the stable alias, not the per-deploy …-<hash>.vercel.app URLs — those change on every push.

Quickstart #

Submit a virtual card design and read the verdict — one request.

Check a design 
curl -N -X POST "https://card-art-checker.vercel.app/api/card-check" \
  -F "file=@card.png" \
  -F "projectId=12345" \
  -F "cardType=virtual" \
  -F "reference=cardArtForm_01HX9"

# event: progress
# data: {"step":"upload","message":"File received","status":"done"}
# … progress for about two minutes …
# event: complete
# data: {"runId":"msqz4i4j-6fa7c9","outcome":"requires_changes","result":{…},…}
async function checkCardArt(art: Buffer, projectId: string, reference: string) {
  const form = new FormData()
  form.append("file", new Blob([art], { type: "image/png" }), "card.png")
  form.append("projectId", projectId)
  form.append("cardType", "virtual")
  form.append("reference", reference)

  const res = await fetch("https://card-art-checker.vercel.app/api/card-check", {
    method: "POST",
    body: form,
    signal: AbortSignal.timeout(6 * 60_000), // runs take ~2 min; allow 5+
  })

  // Read events until the run ends. Each is "event: <type>\ndata: <json>\n\n".
  const decoder = new TextDecoder()
  let buffer = ""
  for await (const chunk of res.body!) {
    buffer += decoder.decode(chunk, { stream: true })
    let end
    while ((end = buffer.indexOf("\n\n")) !== -1) {
      const frame = buffer.slice(0, end)
      buffer = buffer.slice(end + 2)
      const type = frame.match(/^event: (\w+)/)?.[1]
      const data = JSON.parse(frame.slice(frame.indexOf("data: ") + 6))
      if (type === "complete") return data.result   // the result object
      if (type === "error") throw new Error(`${data.code}: ${data.message}`)
    }
  }
  throw new Error("Stream closed before the check finished — resubmit")
}

Give your HTTP client a timeout of at least 5 minutes and read the stream to the end. A check that finishes after your client gives up still runs, but its verdict only reaches you through a webhook.

Access #

No token. Every request carries your Rocketlane project id, and that is what gates the service: the id is looked up in Rocketlane before any analysis starts, and a missing or unknown id ends the request within seconds with missing_project_id.

Your project id is the number of your Rain onboarding project in Rocketlane. Ask your Rain contact if you don't have it.

Submit a check #

POST /api/card-check Rocketlane project id

Send the art as multipart/form-data. The response is a Server-Sent Events stream (text/event-stream): progress while the check runs, then one final event with the verdict. Keep the connection open until that final event.

Events #

Each event is an event: line and a one-line JSON data: line, followed by a blank line. Exactly one of complete or error ends the stream.

EventDataMeaning
progress{ step, message, status }A step started (pending) or finished (done). Informational.
agent_delta, agent_toolnarrationThe reviewer's live notes, for the playground. Ignore them.
complete{ runId, outcome, pdfUrl, result, … }The check finished. result is the result object.
error{ code, message, step }The check couldn't finish. code is from the closed error set.
Final events 
event: complete
data: {"runId":"msqz4i4j-6fa7c9","outcome":"requires_changes","pdfUrl":"https://….public.blob.vercel-storage.com/reports/….pdf","result":{…},…}

event: error
data: {"code":"missing_project_id","message":"Rocketlane project lookup failed: 404","step":"rocketlane"}

Read result from complete. outcome and pdfUrl repeat at the top level; the other fields serve the browser playground. In the rare case the result couldn't be built, result is null — fall back to status (pass or fail) and summary.

Request problems #

Once the stream starts the HTTP status is 200, so a problem with the request arrives as an error event:

  • missing_project_id — no projectId, or one Rocketlane doesn't know.
  • card_art_missing — no file in the request.
  • card_type_indeterminate — an invalid cardType, or none sent and a filename it can't be inferred from.
  • function_timeout — the upload took longer than 30s to arrive.

Only a body that isn't multipart gets a plain-text 400: Bad request: expected multipart/form-data.

Webhooks #

Optional. Besides the stream, the result can be pushed to an HTTPS endpoint of yours — a safety net if your connection drops. It needs one change on our side: Rain either points the default webhook at your endpoint, or allowlists your host so a per-request callbackUrl is honored. Ask your Rain contact for either, and for the webhook signing secret.

Verifying the signature #

HMAC-SHA256 over {timestamp}.{rawBody}, keyed with the webhook signing secret Rain gives you. The timestamp is inside the signed material, so it can't be swapped; reject anything older than a few minutes and a captured request can't be replayed either.

verify.ts 
import { createHmac, timingSafeEqual } from "node:crypto"

const MAX_AGE_S = 300

function verify(rawBody: string, headers: Record<string, string>, secret: string) {
  const ts = headers["x-card-art-timestamp"]
  if (!ts || Math.abs(Date.now() / 1000 - Number(ts)) > MAX_AGE_S) return false

  const expected = "sha256=" + createHmac("sha256", secret)
    .update(`${ts}.${rawBody}`)
    .digest("hex")

  const a = Buffer.from(expected)
  const b = Buffer.from(headers["x-card-art-signature"] ?? "")
  return a.length === b.length && timingSafeEqual(a, b)
}

Verify against the raw body, before JSON parsing. Re-serializing changes the bytes and the signature will never match.

Per-request callbackUrl #

  • It must be https.
  • Its host, or a parent domain of it, must be on the allowlist — hooks.example.com passes when example.com is listed.
  • It replaces the default webhook for that run. A callbackUrl that fails these rules sends nothing; there is no fallback to the default.

Delivery semantics #

Retries3 attempts, 500ms then 1s apart
Retried on5xx, 408, 429, timeouts and network errors
Not retriedany other 4xx
Timeout10s per attempt
Near the deadlinean attempt that can't finish before the run's 280s budget is skipped
Physical resultsnever sent — schema_version: "0-internal"
Delivery failurerecorded on the run; never fails the analysis

Respond 2xx quickly and do your work afterward. A retry after a slow response can deliver the same result twice, so deduplicate on run_id + attachment_id. If you also read the stream to the end, a missed delivery costs you nothing.

Field notes #

FieldNotes
outcome The review decision. Branch on this.
status Legacy top-level state: pass · fail · error. approved_with_notes collapses to pass, so it erases the distinction you care about — don't decide on it. error means the run broke; see failures.
summary 1–2 sentences explaining the decision, written for the designer. Fits a VARCHAR(1024).
blocking_failures Ids of failing blocker checks and failing technical checks. Empty means nothing blocking. A failing required check also makes the outcome requires_changes but isn't listed here — to list everything that failed, filter checks and tech_checks on status: "fail".
checks Always every catalog check — 22 for virtual. One the analysis didn't report is unverified with a note, so a missing verdict never reads as a pass.
checks[].id The contract. Bind to this. Each links to its entry in the check catalog.
checks[].name Display text. Never match on it.
checks[].reason_code Set on fail and warning, null otherwise. One of the check's codes in the catalog, or a universal code.
checks[].marker Normalized 0–1 coordinates on the art — {x: 0.84, y: 0.82} is lower-right. Absent when the issue isn't locatable. Enough to pin the problem on a preview tile.
checks[].merged_from Present when the analysis judged several checks on one line (e.g. "No EMV chip / hologram / magstripe"); each gets the same verdict. Treat those as not independently assessed.
tech_checks id, status, actual, required, note (null when empty), borderline: true on a near miss, and a measurements object when there is one.
counts Checks per status. Only non-zero statuses appear as keys.
submission file_name, plus declared_product when you sent one we recognized.
trigger reference echoes the one you sent.
colors Extracted from the art. Compare against the colors the tenant declared.
unmapped_checks Should always be []. Non-empty means our prompt and catalog have drifted — nothing is dropped, but tell us.

New fields may appear within schema_version: "1.0"; ignore the ones you don't know.

Errors & failures #

A check that couldn't finish still ends with a result, so "this card has problems" stays distinguishable from "the checker fell over". In the stream it is an error event, { code, message, step }; a webhook gets the full failure result below.

Never reject a design on a failure result. Leave the submission open and retry.

When no result arrives #

If the stream closes without a complete or error event — your client timed out, or the connection dropped — treat the check as failed and resubmit.

Every analyzed file gets exactly one result. A check about to hit the platform's 300-second ceiling publishes a function_timeout failure, pushed to your webhook as card_art_check.failed like any other.

Limits #

Run durationUsually about two minutes; give your HTTP client a timeout of at least 5 minutes. The function ceiling is 300s; the pipeline self-limits at 280s so it degrades rather than dying mid-step, and won't start the visual review with less than 150s left (visual_budget_exhausted).
Results per runOne per analyzed file. A run covering several attachments returns several results, each with its own attachment_id.
Virtual onlyPhysical results carry schema_version: "0-internal", are never pushed to webhooks, and their enums may change without notice.
Multipart parse30s. A slower upload fails with Multipart parse timed out.
Report URLsPublic and permanent. Unguessable, but unauthenticated — don't put one anywhere you wouldn't put the report itself.

Token mode Internal #

Rain's own server-to-server integrations can skip the project id and the open connection. The token is the raw value of ROCKETLANE_WEBHOOK_SECRET: one shared secret, not a per-caller credential. It also triggers the Rocketlane flow and reads every run's result, so it never leaves Rain.

Headers — either one 
Authorization: Bearer <ROCKETLANE_WEBHOOK_SECRET>
x-webhook-secret: <ROCKETLANE_WEBHOOK_SECRET>

With the token, POST /api/card-check?async=1 answers { ok, queued, runId, projectId, reference, cardType } as soon as the file is parsed, and the check runs in the background; projectId becomes optional. Read the verdict from a webhook or GET /api/result/{runId}. A request problem is a 400 { error, runId } instead of an error event. Without a valid token, ?async=1 is ignored and the caller gets the event stream.

  -F "cardType=virtual" \

Fetch a result Internal #

GET /api/result/{runId} Token

One run can analyze several files, so this returns every stored result for the run — each with its own attachment_id. Poll every 15–30 seconds; a run with no result 6 minutes after it was submitted has failed.

StatusBodyMeaning
200 { runId, count, results[] } Done. See the result object.
404 { error, runId, hint } Still running, or unknown run. The normal answer while waiting.
400 { error } Missing runId, or Malformed runId — run ids look like msqz4i4j-6fa7c9.
401 Unauthorized (text) Bad or missing token.
500 Server misconfigured (text) The deployment has no ROCKETLANE_WEBHOOK_SECRET.
502 { error: "Result lookup failed" } The result store could not be read. Retry.

Rocketlane trigger Internal #

POST /api/card-art-check?projectId={id} Bearer token

The project-keyed entry point, driven by a Rocketlane Form completed automation. Instead of a file upload it takes a project id and finds the art itself. Integrations outside Rocketlane should post the file directly.

  • Explicit attachments. Ids in data-attachment-id="…" anchors anywhere in the payload, an attachmentId query or body field — each is analyzed as given, as a separate result.
  • Otherwise, auto-resolved. The form webhook carries no file answers, so the files come from the project's latest card-art submission task. When that holds several files (art plus a logo), only the largest image by pixel area is analyzed.
InputDescription
projectId Required Numeric Rocketlane project id. Query string wins over the JSON body. Routes Slack delivery and the report path. Also accepted as /api/card-art-check/{projectId}.
cardType Optional Applies to every attachment in the request. .ai and .eps always run physical regardless.
callbackUrl Optional Allowlist-gated, same as /api/card-check.
declaredProduct Optional Query string or body. Same as /api/card-check.

Finding and downloading the art happens before the response, so the status code tells you whether it was retrieved:

StatusBodyMeaning
200{ ok, queued: true, projectId, runId, analyzing[], downloaded[], failed[] }Analysis started for the ids in analyzing.
200{ ok, queued: false, projectId, runId, reason }No card art found — nothing to analyze. 200 so Rocketlane doesn't retry.
400{ error, runId }Missing or unresolved projectId.
401Unauthorized (text)Bad or missing secret.
502{ error, projectId, runId, failed }Every download failed; a attachment_download_failed result is emitted.
Manual trigger 
curl -X POST "https://card-art-checker.vercel.app/api/card-art-check?projectId=12345&attachmentId=67890" \
  -H "Authorization: Bearer $ROCKETLANE_WEBHOOK_SECRET"

Server configuration Internal #

The environment variables behind the partner-facing behavior above.

VariableControls
ROCKETLANE_WEBHOOK_SECRETThe token for token mode, /api/result, and the Rocketlane trigger. Also derives the token the pipeline's /api/spec-check self-call carries and the signature on browser deliveries to /api/card-deliver; unset, both refuse every call.
RESULT_WEBHOOK_URLDefault webhook target when a request carries no callbackUrl.
RESULT_WEBHOOK_ALLOWED_HOSTSComma-separated hosts a callbackUrl may point at (subdomains included). Empty means no callbackUrl is honored.
RESULT_WEBHOOK_SECRETSigns outbound webhooks. Unset means no webhook is sent at all.
